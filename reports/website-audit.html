Jack’s Lounge Website Audit

Top priority: the public sites are behind the current application. The custom domain is served by GitHub Pages, while a separate Replit deployment also exists. Neither currently reflects all of the fixes visible in the updated workspace. Publishing to Replit alone will not update the GitHub Pages custom domain.

What changed in the workspace

  • Sticky mobile header now exposes Order Online and (508) 775-0612 without opening the menu. The number links to tel:+15087750612; ordering links directly to SpotOn.
  • Both mobile actions are 48px tall. Layouts were checked visually at 320px and 390px, plus desktop at 1440px. Navigation switches to the full desktop layout at wide screens to avoid tablet overflow.
  • Removed the redundant fixed mobile bottom ordering bar and its reserved padding. The menu drawer is scrollable, and desktop floating controls remain.
  • Compressed 14 oversized food images from 50.58 MB to 1.99 MB combined, a 96.1% reduction. This is the total across those asset variants, not the bytes every visitor downloads.
  • Non-home routes no longer preload or briefly display the homepage hero image.
  • Browser titles, descriptions, canonical URLs, social metadata, and shared route schema now use the same route definitions as the server and static build, including client-side navigation.
  • Corrected residual fallback/footer wording that implied honey pizza existed in 1963. The restaurant opened in 1963; the DiPrete family introduced its Famous Honey Pizza after taking over in 1985. Original honey and hot honey remain distinct.
  • The no-JavaScript contact fallback includes all three configured service schedules: dine-in, takeout, and delivery. Schema dine-in hours match the configured hours.
  • Fixed the GitHub Pages build reference from the missing JavaScript generator to the existing TypeScript generator, and disabled the admin route in that public static build. No workflow was triggered.

Unchanged: menu prices, review excerpts and ratings, the direct SpotOn destination, and the existing homepage/menu H1 wording. No dedicated ordering page or ordering embed was added.

The LCP good-experience benchmark is 2.5 seconds; the local menu and existing published Replit mobile samples exceed it. A fast load event does not mean the page is visibly ready.

No uncaught page exceptions, HTTP error responses, or horizontal overflow appeared in the measured homepage/menu samples. Mobile call and order links were correctly positioned with 48px heights. Lazy images not requested within the observation window were not treated as broken images.

Limitations: these are not Lighthouse scores, a formal SEO score, or field Core Web Vitals. Google’s public PageSpeed endpoint returned quota error 429. INP was not measured because no representative interaction set or real-user data was collected. Cross-origin resources may omit transfer sizes; timing varies with network state, connection reuse, and machine load. Repeat measurements on the intended published host before making broad speed claims.

  2. Slow-mobile menu: repeat a compressed-host measurement, then address initial bundle/CSS and page-loading delay if needed. Do not hide this issue behind the faster desktop numbers.

  4. Business data: configured address, phone, and service schedules are consistent in the checked application surfaces. This checks website consistency, not independent verification of current restaurant operations.
  5. Reviews and ordering: existing excerpts and ratings were left untouched. External ordering is not itself an SEO penalty; no dedicated order page or embed is planned.
